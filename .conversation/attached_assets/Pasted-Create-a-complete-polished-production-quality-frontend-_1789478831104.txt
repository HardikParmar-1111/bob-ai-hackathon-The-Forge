Create a complete, polished, production-quality frontend prototype for an enterprise web application called:

# Clinical Trial Risk Monitor

The product is a clinical-trial oversight and protocol-risk monitoring platform.

IMPORTANT:
This task is FRONTEND ONLY.

Do not implement Supabase, PostgreSQL, real authentication, APIs, Python services, AI APIs, real clinical calculations, or real patient data.

Use realistic fictional/mock data only.

The frontend must be architected so the mocked data layer can later be replaced by Supabase/API services without redesigning the UI.

---

# TECHNOLOGY

Use:

* Next.js App Router
* TypeScript
* Tailwind CSS
* shadcn/ui
* Lucide React icons
* Recharts for charts
* React Hook Form
* Zod validation
* Responsive layout
* Accessible UI components
* Component-driven architecture

Use clean reusable components rather than putting everything into large page files.

# PRODUCT USERS

There are two frontend personas:

## Risk Manager

Cross-site oversight user.

Needs to:

* Monitor all authorized trial sites
* Review site risk indicators
* Review protocol findings
* Investigate deviations
* Monitor CAPA
* Review trends
* Search/filter findings
* View detailed site and finding information

## Site Administrator

Site-level user.

Needs to:

* View site status
* Enter participant visit records
* Enter dosing records
* Enter adverse-event records
* View protocol findings
* Review assigned CAPA actions
* Track pending work

# COLOR SEMANTICS

Use restrained semantic colors:

Neutral:

* background
* foreground
* muted
* border

Risk semantics:

* Normal / low concern = green

* Informational = blue

Risk colors should primarily appear in:

* status badges
* indicators
* chart segments
* alerts
* small visual accents
